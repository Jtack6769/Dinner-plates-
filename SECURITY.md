# Project Rules

## General Rules
1. Be respectful to all contributors.
2. No harassment, discrimination, or hate speech.
3. Keep discussions related to the project.
4. Use clear and descriptive commit messages.
5. Test changes before submitting pull requests.
6. Do not submit malware, viruses, or malicious code.
7. Do not intentionally break project functionality.
8. Follow all applicable laws and GitHub Terms of Service.

## Contribution Rules
1. Fork the repository before making major changes.
2. Create a separate branch for each feature or fix.
3. Keep pull requests focused on one issue.
4. Document new features and significant changes.
5. Ensure code follows the project's style guidelines.
6. Resolve merge conflicts before requesting review.

## Security Rules
1. Do not publicly disclose security vulnerabilities.
2. Report vulnerabilities privately to the maintainers.
3. Include detailed steps to reproduce the issue.
4. Allow maintainers reasonable time to investigate and fix issues.
5. Do not exploit vulnerabilities beyond proof-of-concept testing.
6. Do not access, modify, or distribute data that does not belong to you.

## Content Rules
1. No spam, advertisements, or irrelevant content.
2. No copyrighted content without permission.
3. No NSFW or offensive material.
4. Keep issue reports constructive and detailed.

## Enforcement
Failure to follow these rules may result in:
- Warning
- Removal of content
- Temporary suspension from contributing
- Permanent ban from the project

## Reporting a Vulnerability

If you discover a security vulnerability in this project, please report it privately and do not create a public issue.

### Contact Methods

- GitHub: https://github.com
- getreportgh1@gmail.com sA
- Email: jtack2027@gmail.com

### Response Policy

- Reports will be reviewed as soon as possible.
- Valid security issues will be investigated and patched when feasible.
- Please include detailed information about the vulnerability, including steps to reproduce it.
- Do not publicly disclose vulnerabilities until they have been reviewed and addressed.
- Abuse, spam, or intentionally false reports may be ignored.

Thank you for helping improve the security of this project.
